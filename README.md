# НАНОБОТЫ

Сайт анимационного образовательного проекта ООО «4МЕДС».

## Публикация на GitHub Pages

Готовая публичная версия находится в `docs/`. В Settings → Pages выберите **Deploy from a branch**, ветку `main` и каталог `/docs`, затем Save. Дополнительная сборка не требуется.

Веб-версия содержит главную страницу с полноэкранным постером, карточки персонажей, карту тела, ссылки на серии и соцсети.

## Автоматическая статистика аудитории

Блок «Наноботы в цифрах» получает подписчиков YouTube и VK, а также просмотры YouTube через официальные API. До первого успешного получения данных блок скрыт. Исторические цифры из презентации не используются как текущие.

### Однократное подключение

В [Settings → Secrets and variables → Actions](https://github.com/team4meds-sketch/nanobots-site/settings/secrets/actions) добавьте два **Repository secrets** через **New repository secret**:

| Имя | Значение |
| --- | --- |
| `YOUTUBE_API_KEY` | Ключ проекта Google Cloud с включённым YouTube Data API v3. Ограничьте ключ этим API. Ключ используется серверным заданием, поэтому ограничение по домену браузера не подходит. |
| `VK_ACCESS_TOKEN` | Действующий токен VK API, позволяющий вызвать `groups.getById` для сообщества `nanobotsmult` и прочитать `members_count`. Метод поддерживает сервисные, пользовательские и групповые токены. |

Инструкция Google: https://developers.google.com/youtube/v3/getting-started. Описание метода VK: https://dev.vk.com/ru/method/groups.getById.

Ключи вводите только в защищённые поля GitHub Secrets, не в файлы репозитория и не в переписку. Можно подключить сначала одну площадку: сайт покажет только полученные показатели.

После сохранения секретов откройте [Actions → Update audience statistics](https://github.com/team4meds-sketch/nanobots-site/actions/workflows/update-stats.yml) и нажмите **Run workflow**. Также задание запускается каждый час, на 17-й минуте; GitHub может задерживать плановые запуски. Проверки и результаты видны в журнале задания, значения ключей скрипт не выводит.

### Как устроено обновление

- Скрипт `scripts/update-stats.mjs` сохраняет публичные числовые снимки в `public/content/stats.json` и `docs/content/stats.json`. Секреты в эти файлы не записываются.
- Браузер запрашивает свежий JSON из репозитория и локальную копию, выбирая более новую. Это позволяет получать обновления без пересборки GitHub Pages после каждого коммита робота. Открытая вкладка проверяет данные раз в пять минут; кэш площадок тоже может влиять на задержку.
- При сбое сохраняются последние корректные данные и время их получения. После суток появляется отметка о задержке; снимки старше 30 дней скрываются.
- Подписки разных площадок складываются, но это **не уникальная аудитория**. YouTube округляет число подписчиков. Просмотры относятся только к YouTube, включая разные форматы канала. VK Видео и клипы пока не суммируются.
- `releasedVideos: 30` — число выпущенных роликов, сообщённое владельцем, а не автоматический подсчёт публикаций на разных площадках. При новых выпусках его нужно изменить отдельно.
- В публичном репозитории GitHub может отключить расписание после 60 дней без активности. В таком случае включите workflow повторно в Actions.

Проверка скрипта: `node --test scripts/update-stats.test.mjs`. Локальный запуск с переменными окружения: `node scripts/update-stats.mjs`.

## Как обновить серии и новости

Для GitHub Pages отредактируйте `docs/content/entries.json` через GitHub. Это список записей; пустой список `[]` показывает ссылки на официальные каналы. Не публикуйте черновики или конфиденциальные материалы в публичном репозитории.

Запись серии:
```json
{"id":1,"kind":"episode","title":"Название серии","summary":"Краткое описание","body":"","date":"2026-09-18","cover":"./art/poster.jpg","video_url":"https://vk.ru/nanobotsmult","published":1}
```
Для новости используйте `kind: "news"`, текст в `body`, и пустой `video_url`. Реальные ссылки на видео и тексты добавляет редактор. Видео размещаются на внешних площадках.

При пересборке источником контента служит `public/content/entries.json`: перенесите туда изменения из `docs/content/entries.json`, иначе они будут заменены.

## Исходный сайт и редакция

Папки `app/`, `components/`, `lib/`, `public/` содержат исходники, включая текущую серверную редакцию `/admin`. Она использует Cloudflare D1/R2 и авторизацию Sites. GitHub Pages обслуживает только публичную статическую версию; редакция на нём не запускается. Для её переноса на другой сервер нужно подключить базу, хранилище и заменить авторизацию.

Данные из рабочей D1-базы и файлы из R2 в этот экспорт не включены. Публичная версия пока использует пустой каталог серий и новостей со ссылками на официальные каналы.

## Пересборка публичной версии

Требуется Node.js 22.13 или новее и зависимости из `package.json`.
```sh
npm install
npm run build:pages
```
После сборки сохраните изменения в `docs/` в GitHub. `scripts/build-pages.mjs` собирает те же компоненты главной страницы; серверный код не попадает в публичный JavaScript.

## Права

Изображения, персонажи, логотип и материалы проекта предоставлены правообладателем. Публичность репозитория не предоставляет лицензию на их использование. Лицензии зависимостей и сторонних компонентов сохраняются.


## Заявки партнёров

Кнопки в медиаките открывают общую форму с выбранным направлением. HTML POST отправляется в FormSubmit; основной адрес — Dombrovlad@4meds.ru, копия — Valikova@4meds.ru. В письме будут имя, контакты, компания, направление и комментарий. Имя и хотя бы один способ связи обязательны. CAPTCHA сервиса сохранена, дополнительно используется поле-ловушка от спама.

Перед началом приёма заявок владелец основного адреса должен один раз отправить форму с сайта и подтвердить адрес по письму FormSubmit. После подтверждения нужно отправить контрольную заявку и проверить оба ящика. Сам факт успешной сборки сайта не подтверждает доставку писем. Инструкция сервиса: https://formsubmit.co/.

Отправка использует внешнюю страницу подтверждения FormSubmit. При недоступности сервиса в форме есть ссылка для письма напрямую обоим получателям. Изменять получателей можно в `components/partner-contact-form.tsx`, после чего нужно пересобрать `docs/`.
